# Local deployment and security readiness

> WeedSpot Day 35 V3 | Evidence reviewed 2026-11-13. [Index](README.md) | [Root](../../README.md)

**Supported demonstrated setup:** Windows PowerShell 5.1 with `C:\DevEnvs\ai-general\Scripts\python.exe`, Vite dev server `127.0.0.1:5173`, Uvicorn `127.0.0.1:8000`, user-provided local screenshot of image inference. This is **not evidence of public/cloud production deployment**.

```powershell
cd 'D:\porto\100 day\day 35'
$Python = 'C:\DevEnvs\ai-general\Scripts\python.exe'
& $Python -m pip install -r backend\requirements.txt
cd frontend
npm ci
npm run build
cd ..
# Terminal 1 (stays running)
.\scripts\run_backend.ps1
# Terminal 2 (new PowerShell tab, from repo root)
.\scripts\run_frontend.ps1
```
Open `http://127.0.0.1:5173`; API schema at `http://127.0.0.1:8000/docs`. Both run scripts assume the **Windows-only shared Python path** above, so other installations must edit `scripts/run_backend.ps1` or run `python -m uvicorn app.main:app` from `backend/` with their own interpreter. `best.pt` must be provisioned separately at `models/best.pt`; it is intentionally ignored by Git.

**Preflight:** correct `models/best.pt` and checksum, backend requirements installed, frontend `npm ci`, ports unused, readiness returns true, and a supported image gives prediction output. Browser and API run separately. `frontend/dist/` is generated by `npm run build` but no static hosting method is implemented by these scripts.

**Security gates before public launch:** set explicit trusted origins, reverse-proxy TLS, authentication/authorization, abuse/rate limits, image decompression attack tests, request size limits at proxy, resource timeouts, logging policies and retention, dependency/vulnerability review, server concurrency metrics, privacy notice/consent, secure artifact distribution, dataset licensing and field evaluation. Avoid presenting the current image upload wording as a guarantee about third-party logging or hosting.

**Environment file caveat:** the tracked `.env.example` mentions `APP_PORT=8012` and `MODEL_PATH=models/best_model.onnx`, but **the current Python and PowerShell sources do not consume those settings**: actual default backend port 8000 and model path `models/best.pt`. These lines are legacy examples, not active configuration knobs. Do not rely on them for deployment.
